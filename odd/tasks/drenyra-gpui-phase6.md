  - T10 design (decided by the parent under S6; the user asked for best practice and left choices open):

New `replace_human_approval(expected_previous: &str, approver) -> Result<(), ReplaceApprovalError>` — compare-and-swap: errors `NothingToReplace` (no approval), `StaleApproval { current }` (expected ≠ current), `SameApprover` (trimmed new == current), `InvalidApprover` (same validation as record). Every error leaves the approval unchanged. Error `Display` strings are user-facing English sentences.
    2. Controller (`DrenyraHostController`): append-only session evidence log per `WorkspaceKey`, `EvidenceEvent { seq: u64 (global, monotonic from 1), kind: EvidenceKind }` with kinds `Staged { proposal_id, risk_tier }`, `Approved { proposal_id, approver }`, `ApprovalReplaced { proposal_id, previous, approver }`, `ApprovalCleared { proposal_id, previous }` (a line decision change cleared it), `PostRequested { proposal_id, request_id }`, `Posted { proposal_id, request_id }`. Read API `evidence(&WorkspaceKey) -> &[EvidenceEvent]`. New mutation methods that log: `approve_active(approver) -> bool`, `replace_active_approval(expected, approver) -> Result<(), ReplaceApprovalError>`, `accept_active_line(idx) -> bool`, `reject_active_line(idx, comment) -> bool` (log `ApprovalCleared` when the call cleared an approval). Events go to the key of the workspace that owns the review (`confirm_posted` may run while another workspace is active). Also keep a per-key list of posted entries (`PostedEntry { proposal, approved_by, request_id }`) captured in `confirm_posted` before the review is removed, read via `posted(&WorkspaceKey)` — used by T11's Ledger pane. Nothing is persisted or signed; doc comments say so.
    3. Shell (`ShellState`): AcceptLine/RejectLine/approval Confirm go only through the controller methods above (no direct `active_review_mut` mutation left in `commands.rs`). `ApprovalDialogView` gains `current_approver: Option<String>`; Confirm with no approval → `approve_active`; with an approval → `replace_active_approval(current, typed)`, mapping errors to the dialog error (same ID → "Already approved by <id>."). The dialog (window.rs) shows "Approved by <id>. Confirming replaces that approval; both stay in the evidence log." when one exists.
